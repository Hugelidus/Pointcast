# Evaluation pilot — does pointcast help a coding agent? (2026-09-27)

**Question.** Given the same UI change request, does a coding agent identify the right elements more reliably, faster or with fewer tokens when it receives a pointcast `session.md` instead of text?

## Setup

- **App:** `dev/playground/` (one HTML page plus CSS; deliberately tiny).
- **Request:** a real 43 s Spanish recording (5 changes: sort the table by quantity, make the Export button violet, make the header red, remove the Notes paragraph, hide Settings behind a toggle while keeping the API token field visible).
- **Agent under test:** Claude Sonnet as a sub-agent, medium effort, read-only. Task: list every requested change with file, locator and confidence. 3 independent runs per condition; none of them saw the answer.
- **Conditions:**
  - **P — pointcast:** the generated `session.md`.
  - **M1 — same words, no pointing:** the transcript of what the user said ("esta tabla…", "este botón…", "esta barra…"), as if typed or dictated without pointing.
  - **M2 — careful manual description:** a precise written request naming each element, as a diligent user would type it ("el botón Export ponlo violeta…").
- **Scoring:** 5 ground-truth changes; a change counts only if the agent picked the right element (for example, recoloring the shared `.primary` class also changes the Save button, so it is wrong).

## Results

| Condition | Correct (of 5), per run | Accuracy | Mean time | Mean tokens | Mean tool calls |
|---|---|---|---|---|---|
| **P — pointcast** | 5, 5, 5 | **100 %** | **82 s** | 74.1 k | 7 |
| M1 — same words, no pointing | 3, 2, 3 | 53 % | 143 s | 74.4 k | 4 |
| M2 — careful manual description | 5, 5, 5 | 100 % | 69 s | 69.8 k | 6.3 |

Errors in M1 were the damaging kind: recoloring every `.primary` button (Save included), painting the toolbar instead of the header, deleting the page's instructions block instead of the Notes paragraph.

## What this shows

- **Pointing removes ambiguity.** With the words the user actually said, the agent got about half the changes wrong; with pointcast it got all of them right, matching a careful written description that the user did not have to write.
- **Time:** pointcast runs finished 43 % faster than M1 (less deliberation over ambiguous references) and ~13 s slower than M2 (the spec is richer to read).
- **Tokens: no measurable saving here, as expected.** Most of the ~70 k tokens per run are the agent's fixed context. In a one-file app, finding an element costs almost nothing, so pointcast's richer spec (~4 k tokens more than M2) is not offset by fewer searches.

## Limits (read before quoting)

- One scenario, one tiny app, 3 runs per condition, one model: a pilot, not a benchmark.
- Identification only; the agents did not implement the changes.
- Token savings need a realistic codebase where locating an element takes searching across many files. That is the next evaluation, on apps built with different stacks.
